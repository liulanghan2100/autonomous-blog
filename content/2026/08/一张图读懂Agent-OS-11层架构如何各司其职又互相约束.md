# 一张图读懂Agent OS：11层架构如何各司其职又互相约束

> 架构图的价值不在于"画得漂亮"，而在于一眼能看出：谁在干活、谁在把关、数据往哪流、能力从哪来。

## 开头：先看这张总览图

最近拆解了一份 Agent OS Core（智能体操作系统核心）的分层架构，作者在文档末尾附了一张 mermaid 总览图。信息量很大，但如果只看节点不关心连线，等于没看懂。这篇文章就按"**数据流 + 约束流 + 回流**"三条线索把这张图讲透。

```mermaid
flowchart TD
    A["0. 治理宪法层<br/>管边界"] --> B["1. 七个Agent门面<br/>接任务"]
    B --> C["2. 能力控制平面<br/>管Skill/工具/模型"]
    B --> D["3. 调研入口<br/>外部搜索/竞品/开源"]
    C --> E["4. 运行服务<br/>跑任务"]
    D --> E
    E --> F["5. 故障自复位<br/>检测/重试/降级/回滚"]
    C --> G["6. 能力生命周期<br/>准入/蒸馏/进化/发布/退役"]
    G --> C
    E --> H["7. 业务运行层<br/>股票/合同/投研/文档"]
    H --> I["8. 记忆层<br/>历史/偏好/经验"]
    H --> J["9. 知识库<br/>方法论/证据/图谱"]
    D --> K["10. 实验归档<br/>外部项目隔离"]
    K --> G
    F --> I
    F --> J
    A -.约束.-> C D E F G H I J K
```

## 一、三条线读懂这张图

### 线 1：数据主链路（谁在干活）

```
B(七Agent门面) → C(能力控制平面) → E(运行服务) → H(业务运行) → I/J(记忆+知识库)
```

任务的真实路径是：**Agent 入口 → 调能力 → 执行 → 产出业务结果 → 沉淀记忆/知识**。注意 H（业务运行层）是末端，它只跑业务（股票/合同/投研/文档），**不碰系统底层**——这是典型的"业务与平台分离"。

### 线 2：约束流（谁在把关）

```
A(治理宪法) -.约束.-> C D E F G H I J K
```

图中最醒目的是虚线：**第 0 层宪法用虚线指向除了 B 以外的所有层**。含义很清楚：宪法不直接干活，但它给每一层划边界——门禁、审批、证据、审计、成本、权限，全部是系统级强制。B（Agent 门面）没被直接约束，因为 Agent 只是入口，真正干事的 C/D/E/F/G/H/I/J/K 全在宪法射程内。

### 线 3：回流（能力从哪来、经验往哪去）

图中藏着三条回流，是最容易被忽略的设计：

```
K(实验归档) → G(能力生命周期) → C(能力控制平面)   # 外部项目吸收机制，蒸馏成 Skill 回流
F(故障自复位) → I/J(记忆/知识库)                 # 故障经验沉淀，越用越懂自己的坑
G → C                                           # 新 Skill 经生命周期后登记进能力库
```

这三条回流让系统不是"一次性搭建"，而是**可持续进化**：外部好机制先进实验区隔离研究，蒸馏成 Skill 后回流；故障不白犯，沉淀成记忆和知识。

## 三、这张图最值得细品的三个设计

### 1. 治理宪法为什么"只约束不干活"（虚线设计）

宪法用**虚线**连所有层，而不是实线。实线表示"数据流过"，虚线表示"规则约束"。这个区分很高级：宪法不参与数据流（否则它就成了单点瓶颈），但它以钩子形式注入每层的行为边界。**约束是横向的，执行是纵向的**——这是治理层该有的姿态。

### 2. 实验归档层的"隔离吸收"闭环

`K → G → C` 这条回流是防"外部先进能力污染核心"的关键：Firecrawl/Cognee/Omnigent/Better Harness 全先进 Lab 隔离研究，吸收机制后由 G（能力生命周期）蒸馏成自己的 Skill，再登记进 C（能力控制平面）。**吸收的是机制，不是代码**。

### 3. 故障自复位"向记忆和知识库双向沉淀"

`F → I`（故障进记忆）和 `F → J`（故障进知识库）同时存在。区别在于：记忆层存"这次发生了什么、怎么修好的"（情境化），知识库存"这类问题该用什么方法"（结构化）。**同一份教训，两处沉淀，一次调用两种用法**。

## 四、我的四点分析意见

1. **B 没被宪法约束是个潜在漏洞**：图中 A 的虚线指向 C~K 但没指 B。虽然 B 只是门面，但如果 Agent 门面能自定义自己的 prompt 和工具偏好，约束就可能被"绕过"。建议 B 也纳入宪法射程。

2. **H（业务运行）依赖 I/J，但 I/J 不依赖 H**：记忆和知识库是单向承接业务产出的。这意味着业务层如果产出质量差，记忆层会"记住错误经验"。建议在 H→I/J 之间加一层"经验质检"（参考第 5 层的错误分类器）。

3. **回流有环但没画收敛点**：K→G→C 和 F→I/J 都是回流，但图里没有"进化总开关"——什么条件下允许回流生效。建议由 0 层宪法统一定义回流准入（比如 Skill 需在 Lab 内成功 X 次才允许蒸馏）。

4. **可观测性在第 4 层但没进主线**：图里可观测性（metrics/logs/traces/alerts）属于运行服务层，但没画出它对治理层的反馈。建议加一条 F/A 之间的虚线：故障与审计实时回传宪法层，让门禁动态收紧。

## 总结

这张 11 层架构图，本质上是三件事的平衡：

- **纵向**：任务沿主链路流动（Agent → 能力 → 运行 → 业务 → 记忆）
- **横向**：宪法约束每一层边界（证据/审批/审计/成本）
- **环形**：外部机制与故障经验通过回流实现持续进化

**先有边界，再谈能力；先能复盘，再谈进化**——这就是这张图想说的全部。
